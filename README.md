# prpg

A GitHub template for a 2D top-down **pseudo-RPG**: walk a tile map, talk to characters through
[Ink](https://www.inklestudios.com/ink/) dialogue, play small **activities** (minigames) launched
from the map, and progress through **acts**. Each act is a self-contained **content pack** with its
own maps, so an act can ship inside the game or later as **DLC**, with no base-game rebuild.

Built on [libGDX](https://libgdx.com/) with Dagger (DI), Ashley (ECS), blade-ink (Ink runtime),
SnakeYAML (content), Tiled (maps) and an Aseprite-to-atlas art pipeline. Desktop (LWJGL3) and
Android targets, GitHub Actions CI, Dependabot, and a set of pure-JVM content guard rails.

Use **"Use this template"** on GitHub, then follow [Getting started](#getting-started).

---

## What you get

- A playable sample act, **The Gatehouse** (`packs/act1`): two maps, a keeper who moves between
  them as the story advances, a match-3 hedge that physically blocks a door, a lights-out strongbox
  that opens in a **popup** over the world, a merge workbench, a bench that advances the day, a
  walk-in cutscene trigger, a quest, and an act boundary that hands off to act 2.
- A DLC sample act, **The Road** (`packs/act2`), not bundled: `./gradlew shipPack -Ppack=act2`
  zips it; drop the zip into the content root and the keeper's "road" branch opens.
- Three activity kinds to copy from: two **full-screen** (`match3`, `merge`) and one **popup**
  (`lightsout`). Adding a kind is one class plus one Dagger binding.
- Placeholder art generated by the build (no licensed art in the repo), a Tiled project with the
  object classes pre-declared, and the Aseprite pipeline for when real art arrives.
- Guard-rail tests that fail on any dangling reference in content (`./gradlew validatePacks`).

## Getting started

Prerequisites: JDK 21 (the Gradle wrapper is included), and for the Android target an Android SDK
(`sdk.dir` in `local.properties`; see `local.properties.example`).

```bash
./gradlew lwjgl3:run          # play the sample act on the desktop
./gradlew :core:test          # unit tests + content guard rails
./gradlew build test          # what CI runs (also builds the Android APK)
```

Controls: WASD / arrows to move, E or Space to interact (or tap), I / Tab inventory, Q quest log,
F5 save, Esc back. Touch works throughout (hold to steer, tap to interact).

`org.gradle.daemon=false` is set on purpose, so every `./gradlew` starts a fresh JVM and feels
slow. Flip it in `gradle.properties` if you prefer.

### Make it your game

1. **Rename** (all optional but do them together):
   - `extra["appName"]` in `build.gradle.kts` (window title, jar names, Preferences name, and the
     per-user content root `~/.<appName>/`).
   - `title` in `packs/baseline/config/game.yaml` (main menu).
   - Java package `com.prpg` (IDE rename; then update `mainClass` in `lwjgl3/build.gradle.kts`,
     `namespace`/`applicationId` in `android/build.gradle.kts`, `AndroidManifest.xml`, the
     `generateAppInfo` task in `core/build.gradle.kts`, and the `com.prpg.build.*` references in
     the root `build.gradle.kts`). Keep YAML POJOs in a `config` package: the R8 keep rule matches it.
   - `android/res/values/strings.xml` (`app_name`), icons under `android/res/` and `lwjgl3/icons/`.
   - `LICENSE`. The template ships MIT; pick what your game needs.
2. **Replace the sample content.** Either edit `packs/act1` in place or scaffold a fresh act with
   `./gradlew newPack -Ppack=act1 -Porder=1` after deleting the sample, then set `bundled: true`
   in its `pack.yaml`. Delete `packs/act2` if you don't want the DLC sample.
3. **Read** [`docs/content-guide.md`](docs/content-guide.md). It is the contract between content
   files and the engine: map layers, staging, Ink bridge functions, activity definitions, flags.
4. Set up the repo on GitHub: enable Actions, and add a branch-protection rule on `main` that
   requires the `build` job if you want the auto-merge workflows to wait for CI.

## Project layout

```
core/       game code (com.prpg.TheGame) and the Dagger graph
lwjgl3/     desktop launcher, fat-jar + Construo native bundles
android/    Android launcher, manifest, resources
packs/      the content tree: baseline/ (shared) + one folder per act
assets/     bundled-pack staging area (generated at build time, gitignored)
art/        the Tiled project and the Aseprite Lua tool
buildSrc/   build tools: Ink compiler, pack tool, pack scaffold, placeholder art
docs/       content-guide.md (authoring contract), logging.md
.github/    CI (build + test), Dependabot, auto-merge workflows
```

### Packs

```
packs/baseline/            shared engine content (ships in the app)
  config/game.yaml         engine tunables (player speed, view size)
  ui/ fonts/ i18n/         Scene2D skin, dialogue TTFs, string bundle
  items/items.yaml         the item catalog (inventory outlives any act)
  ink/common/bridge.ink    the Ink <-> Java EXTERNAL declarations
  narrative/manifest.yaml  the act catalog (advertises DLC that isn't installed)
  sprites/ art/ atlases/   player + generic NPC sprites (descriptor, Aseprite source, packed atlas)
  tilesets/basic.*         the placeholder tileset any pack may reference
packs/act1/                a bundled act (pack.yaml: bundled: true)
  pack.yaml                id, order, entryMap/entrySpawn, declared flags, generated files: list
  maps/*.tmx               the act's own maps (Tiled), tilesets by relative path
  staging/act1.yaml        who/what is where during this act, against map markers
  activities/<type>/*.yaml activity definitions (match3, merge, lightsout)
  quests/*.yaml            flag-derived quest steps
  actors/*.yaml            character identities (name, colour, sprite)
  ink/act1.ink             the act's story; narrative/act1.ink.json is the compiled output
  flags.yaml               every flag this act's content references
packs/act2/                a DLC act (bundled: false), shipped as a zip
```

**There is no base map.** Every map belongs to an act, and an act's `pack.yaml` names the map and
spawn it opens on. When `ActProgression` advances the act (Ink calls `advance_act()`), the world
screen moves the player to the new act's entry map. The baseline never needs to know map names.

## How the pieces fit

- **Dagger** (`core/.../di/GameComponent`) wires three modules. Everything content refers to by
  string is a Dagger multibinding: activity types, cutscene ids, screens, ECS systems. A new
  activity or cutscene is one class and one `@Provides ... @IntoMap @StringKey("id")` line.
- **Content resolution.** All content is read through `content/ContentResolver`, which checks
  mounted packs first, then bundled assets. At startup `PackMounter` extracts bundled packs and
  installs any dropped `*.zip` into the writable content root (`~/.prpg/content/` on desktop,
  app-private on Android). Packs re-extract only when their `version:` rises, so **after editing
  content during development, delete `~/.prpg/content/`** or you will keep seeing the old copy.
- **Acts are data.** `narrative/content/ActContentRegistry` merges the catalog with each mounted
  pack's `provides:` into an ordered spine. `ActProgression` gates each transition with a
  `GateResult` (narrative not ready / not owned / not installed / advanced), so a paywall and a
  missing download use the same mechanism as story gating. `DefaultEntitlement` owns anything
  catalogued FREE or mounted, plus a `meta.owns.<act>` flag a real store would set.
- **Narrative.** Java owns durable state (`NarrativeState`, `FlagStore`, `Inventory`); an Ink story
  is ephemeral and reaches Java only through `StateBridge`, which binds the `EXTERNAL`s declared
  in `bridge.ink`. Reads are lookahead-safe, writes are not, so a side effect fires exactly once.
  An NPC's dialogue id is an Ink knot name.
- **World.** `WorldScreen` renders the TMX, ticks the Ashley engine, and hosts the dialogue,
  inventory and quest overlays plus popup activities. `StageDirector` resolves the act's staging
  file against the flags every time they change: characters move, obstacles appear and vanish,
  paths open and close, all without reloading the map or touching the save file.
- **Activities.** `ActivityLauncher` maps a `type` string to a `FullScreenActivity` (replaces the
  screen) or a `PopupActivity` (panel over the frozen world). Both share `activities/<type>/<id>.yaml`
  definitions and the same `on_complete` block (`set_flag`, `give_item`, `dialogue`).
- **Save.** One `save.json` under the content root: position, flags, inventory, narrative model,
  Ink resume tokens, staging overrides. Quests and declarative staging are re-derived from flags.

## Commands

```bash
./gradlew lwjgl3:run                     # desktop
./gradlew android:installDebug           # Android (device/emulator attached)
./gradlew lwjgl3:dist                    # desktop fat jar
./gradlew lwjgl3:construo                # native installers (jlink + per-OS bundles)

./gradlew :core:test                     # all unit tests
./gradlew validatePacks                  # content guard rails only (the pre-ship gate)
./gradlew build test --stacktrace        # CI

./gradlew compileInk                     # ink/<id>.ink -> narrative/<id>.ink.json (commit it)
./gradlew generatePackManifests          # refresh each pack.yaml's files: list (commit it)
./gradlew newPack -Ppack=act3 -Porder=3  # scaffold a bootable act (stub map, story, staging)
./gradlew shipPack -Ppack=act2           # manifests + ink + validate + zip -> build/packs/act2-v1.zip
./gradlew packAll                        # zip every pack
./gradlew bundleDlc -Pdlc=road-pack -Ppacks=act2   # group pack zips into a DLC folder

./gradlew genPlaceholderArt              # regenerate the placeholder tileset + character sheets
./gradlew genCharacterAseprites          # PNG sheets -> tagged .aseprite (needs Aseprite)
./gradlew buildAtlases -Ppack=baseline   # .aseprite -> packs/baseline/atlases/baseline.atlas (needs Aseprite)
```

## Art pipeline

Nothing in the repo is licensed third-party art. `genPlaceholderArt` draws a 16x16 tileset and two
48x48 character sheets with plain Java; `genCharacterAseprites` turns sheets into tagged
`.aseprite` files via `art/tools/gen_character_aseprites.lua`; `buildAtlases` exports every tag as
frames and packs them into one atlas per pack. Set `aseprite.bin` in `local.properties` for the last
two. All outputs are committed, so CI never needs Aseprite.

To bring in real art: replace `packs/baseline/art/*.png` (or author `.aseprite` files directly with
tags named `<state>_<direction>`), run `buildAtlases -Ppack=baseline`, then
`generatePackManifests` and `validatePacks`. Tilesets bypass the atlas pipeline: drop a PNG and a
`.tsx` into a pack's `tilesets/` and reference it from Tiled. The player sprite descriptor
(`sprites/player.sprite.yaml`) names the atlas and region prefix, so swapping art is a data change.

Bundled fonts: Liberation Serif (SIL OFL 1.1). UI skin: the libGDX default skin (Apache 2.0).

## Continuous integration

`.github/workflows/ci.yml` runs `./gradlew build test` on every push and pull request to `main`
with JDK 21 and the Android SDK. `dependabot.yml` opens one grouped dependency PR per week;
`auto-dependabot.yml` and `auto-owner.yml` approve and auto-merge PRs from Dependabot and the
repository owner once required checks pass (they need a branch-protection rule requiring the
`build` job, otherwise auto-merge is immediate).

## Tests

JUnit 5 + Mockito, all headless (`gdx-backend-headless`; nothing needs a GL context):

- Pure logic: match-3, merge and lights-out boards, inventory, flags, staging resolution, act
  progression, save round-trips, the Ink bridge driven through the real sample story.
- Guard rails (also run by `validatePacks`): every `dialogue` is a real knot, every item and
  activity id exists, every flag is declared, every portal target and spawn exists, every act's
  entry map exists in its own pack, every Ink `EXTERNAL` is bound, every `pack.yaml` `files:` list
  matches disk, every tileset matches its image, every sprite descriptor's regions are in its atlas.
